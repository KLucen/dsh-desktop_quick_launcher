# dsh-desktop_quick_launcher v0.2.7

**桌面一键启动 / 一键重启 / 优雅退出** 的 DSH Web 插件，并且**绝不切断正在生成的回答**。独立重建自已退役的 `@linxin666/dsh-desktop-launcher`（Apache-2.0）。

An independent, Apache-2.0 rebuild of the retired `@linxin666/dsh-desktop-launcher`:
a double-click desktop icon that starts `dsh web` and opens an **authenticated** Web GUI URL, a
floating panel that rebuilds the shortcut / restarts the service / exits gracefully, and a
Settings card for the panel's buttons and the plugin's own logs.

## 本版修复 / Fixed in this release

- **"桌面快捷方式不存在"误报**（用户报告）：浏览器半边是**从磁盘实时提供**的，所以"装完新版本、刷新页面、但宿主进程还没重启"时会形成错位 —— 新界面配旧宿主。旧宿主的 `/status` 没有 `shortcut` 字段，而新界面把"字段缺失"当成了"快捷方式被删除"，于是在快捷方式明明存在时显示"不存在（可能被删除了）"。本版彻底消除这类误报（见下）。
- **发布流程漏洞（我自己造成的）**：此前我只核对"**已安装的文件**是哪个版本"，从未核对"**正在运行的宿主**是哪个版本"；因此 0.2.6 装上了却从未真正加载（那个延迟重启 worker 在等待中静默退出），错位一直存在。现在每次发布都必须用 `GET /ping` 确认 `pluginVersion`。

## 本版新增 / Added in this release

- **显式的版本错位提示**：客户端把自身版本（`CLIENT_VERSION`）与 `/ping` 的 `pluginVersion` 对比，不一致时在详情面板与设置卡片顶部显示
  `客户端与宿主版本不一致：client vX / host vY` + "请在面板上点「重启服务」让宿主加载新版本"。
- **字段缺失显示为"无法确认"** 而不是"不存在"：`/status` 没有 `shortcut` 字段时提示"当前宿主版本较旧（不含该检测），重启服务后即可看到真实状态"。

## 安装 / Install

```bash
# 固定到本版本（codeload 本机可直连）
dsh plugin --profile web add "https://codeload.github.com/KLucen/dsh-desktop_quick_launcher/tar.gz/refs/tags/v0.2.7"
# 镜像（github.com 不可达时）
dsh plugin --profile web add "https://gh-proxy.com/https://codeload.github.com/KLucen/dsh-desktop_quick_launcher/tar.gz/refs/tags/v0.2.7"
# 跟随 main
dsh plugin --profile web add github:KLucen/dsh-desktop_quick_launcher
```

安装后**必须重启 `dsh web`** 才会加载新版本（本版新增的版本错位提示就是为了让这件事一眼可见）；桌面图标脚本会在每次启动时自动重写，不需要你操作。

## 验证 / Verified before release

- **真实错位现场**：确认宿主为 0.2.5、客户端为 0.2.6，`/status` 无 `shortcut` 字段 → 界面误报"不存在"；本版改动后同样的错位显示版本提示与"无法确认"。
- **重启后核对运行版本**：`GET /ping` → `pluginVersion = 0.2.7`（pid 11376），`GET /status` → `shortcut.exists = true`、`path = C:\Users\KLEE\Desktop\DSH-Web.lnk`。
- **插件自身重启通道端到端**（本版实测记录）：`POST /restart {force:true, graceMs:30000}` → **202** + `helper.method = schtasks`，`restart-helper.log` 记录 `helper started pid=35952`，`restart-status.json` 推进到 `verifying-old`（**启动验证门通过**）→ 19:30:28 起新实例 → **19:30:43 就绪（15.4 秒）**，并捕获到新的 `authUrl`。
- `pnpm typecheck` 通过；`pnpm test` **49/49**。

## 已知限制 / Known limitations

- 重启与退出会终止整个 `dsh web` 进程；会话可恢复，但当前正在生成的回答不会被保留（这正是回合未结束时插件拒绝执行的原因；确需强制时走二次确认的 `force`，报告中记 `forced: true`）。
- busy 检查依赖 live session store；不可用时**放行**并在 `busyCheck` 记录原因（fail-open，避免重启永久失效）。
- nonce 只挡跨站浏览器请求，挡不住本机进程；所有路由仅限回环。
- Windows 图标固定名 `DSH-Web.lnk`，会覆盖同名快捷方式；POSIX 启动器未在真机验证，重启助手仅支持 Windows。
- 小缺口：重启报告（`restart-status.json`）里暂未记录 `helperMethod`（用的是 `schtasks` 还是 `detached`）——HTTP 202 响应里有，文件里缺；属于诊断信息不完整，不影响功能。
